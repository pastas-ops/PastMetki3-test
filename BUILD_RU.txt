PASTAS / PASTMETKI 1.1.0 — ИНСТРУКЦИЯ ПО СБОРКЕ
================================================

ЭТО АРХИВ ИСХОДНОГО ПРОЕКТА ДЛЯ СБОРКИ, А НЕ ГОТОВЫЙ APK.
Android-проект генерируется Capacitor во время подготовки, затем в него
устанавливаются нативные виджеты из папки native/.

САМЫЙ ПРОСТОЙ СПОСОБ: GITHUB ACTIONS
------------------------------------
1. Распакуйте архив в отдельную папку.
2. Создайте новый пустой репозиторий GitHub.
3. Загрузите в корень репозитория ВСЕ файлы и папки из архива.
   Важно: не пропустите скрытую папку .github — в ней лежит сценарий сборки.
4. Сделайте push в ветку main (или default branch). Сборка запускается автоматически.
   Альтернатива: GitHub → Actions → Build APK → Run workflow.
5. Дождитесь зелёного завершения workflow «Build APK».
6. Откройте завершённый запуск workflow, внизу в Artifacts скачайте
   «PastMetki-apk». Внутри будет app-debug.apk.
7. Распакуйте artifact ZIP и установите app-debug.apk на Android.

ЛОКАЛЬНАЯ СБОРКА (Linux / macOS / WSL)
--------------------------------------
Требуются Node.js 20, Java 17, Android SDK и настроенный ANDROID_HOME.
Из корня распакованного проекта выполните:

    npm install
    bash native/prep.sh
    python3 native/install.py
    cd android
    ./gradlew assembleDebug

APK появится здесь:

    android/app/build/outputs/apk/debug/app-debug.apk

ПРОВЕРКИ
--------
GitHub Actions запускает native/verify.sh после сборки. Он проверяет APK,
иконку, версию, разрешения, 12 Android-виджетов и схему deep link pastmetki://.
Если сборка с виджетами ломается, workflow отдельно пытается собрать APK без
виджетов и помечает запуск красным статусом, чтобы отсутствие виджетов не
выглядело как успешная полная сборка.

ОБНОВЛЕНИЕ УЖЕ УСТАНОВЛЕННОГО ПРИЛОЖЕНИЯ
---------------------------------------
В архив включён debug.keystore, используемый этой сборкой для подписи debug APK.
Не удаляйте и не заменяйте его: сохранение того же ключа позволяет устанавливать
новые сборки поверх предыдущих, подписанных этим же ключом. Если Android сообщает
о конфликте подписи, старая версия была подписана другим ключом; тогда её придётся
удалить перед первой установкой этой сборки.

ПУБЛИКАЦИЯ САЙТА
----------------
Сайт находится в папке www/. Для публикации через уже настроенный Firebase-проект
используется команда firebase deploy (после установки firebase-tools и входа
в нужный аккаунт). Это публикует сайт и правила Firestore. Не запускайте эту
команду, если не собираетесь публиковать изменения в Firebase.

Перед публикацией обновления для существующих пользователей сначала соберите APK,
разместите его по постоянной прямой ссылке и только затем заполните поля apk/page
в www/version.json. Сейчас эти поля намеренно пустые, чтобы приложение не показывало
пользователям ссылку на ещё не опубликованный APK.
